# ReadySix → программы зала

ReadySix — основной источник состояния игрока и календаря. Режим по умолчанию `primary`; явный `READYSIX_*_MODE=legacy` оставлен только для управляемого отката. Нужны существующие серверные READYSIX_URL и ключ соответствующей организации. При недоступности источника нет скрытого перехода на локальную оценку.

Генератор показывает исходное решение ReadySix, причины, лимит объёма, ближайшую игру и предложение метода. Применение предложения меняет настройки; генерация/сохранение остаются действиями тренера. Локальные пороги WHOOP и отсутствующие тесты не переопределяют состояние ReadySix. Ограничения тренера могут дополнительно уменьшить нагрузку.

Рекомендация учитывает подтверждённый план дня, MD−1/−2, MD+1, плотность игр и историю сохранённых программ. Последняя не считается доказательством выполнения. Без ближайшей игры не предлагается развивающее окно. В защитные дни несовместимый выбор метода отклоняется с предложением применить подходящий вариант; метод не меняется молча. Состояние на будущую дату требует решения ReadySix; это не прогноз будущей готовности.

Стоп, минимальная индивидуальная работа (≤20%), недостаточное решение, конфликт расписания в ближайшие три дня, подтверждённый день без зала блокируют генерацию до уточнения. Процент ReadySix ограничивает объём, а не вес от 1ПМ. Пока нет проверенных анатомических тегов упражнений, применяется наиболее строгий из общего и силовых региональных лимитов ко всей программе. Это консервативное ограничение уже адаптированного бюджета. Календарь дополнительно ограничивает время, тяжёлые подходы, прыжки и RPE.

## Дополнение API ReadySix

Изолированная ветка `codex/readysix-gym-context`, рабочая копия `/tmp/readysix-gym-context`.

В существующий контракт v1 добавлены:
- `calendar`: реальные события reports config, подтверждённые session schedules, план выбранного дня и конфликты. Область организации задаётся credential-bound storage.
- `decision.recommendationLabel`, `observations`.
- `decision.targets[].healthCapPercent`, `healthRecommendation`, `scheduleCapPercent`, `planApplicability`, `jumpPrescription`.

Оценка здоровья отделена от отсутствия запланированной нагрузки. События читаются от −14 до +90 дней, подтверждённые дневные планы — до +28 дней. Неподтверждённые планы не заменяют календарь. Матч не исчезает при конфликте с выходным. OVERTRAQ и история прыжков теперь принимаются под настоящими именами полей API.

## Выпуск

Сначала выпустить дополнение API ReadySix, затем coach. Проверить организацию и date/revision, совпадение исходного состояния, матч/выходной/предыгровой день, блокировку стоп-сигнала. До выпуска upstream-календаря coach покажет ограниченную рекомендацию без выдуманной даты игры. Производственные данные и deployment этой работой не изменялись. Календарь использует общий calendarDaySchedule ReadySix, включая направленность из Reports Center.

Проверка полного локального потока после сборки: `node scripts/check-readysix-gym-flow.mjs`. Для браузерной части передать QA_BROWSER_MODULE с путём к установленному playwright/index.mjs. Все сервисы подменены синтетическим локальным стендом, внешняя сеть заблокирована. Реальный платный вызов модели этой проверкой не заменяется.
