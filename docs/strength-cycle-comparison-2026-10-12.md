# Сравнение соседних силовых циклов

Одинаковое поведение в zarechie и nkperf. В обзоре выбранного цикла показано сравнение с непосредственным предыдущим циклом, если оба имеют четыре фактически подтверждённых полных выполнения. Незавершённый соседний цикл не пропускается ради более удобной пары. При пересечении дат полных выполнений сравнение заблокировано до проверки истории тренером. Первый доступный цикл не имеет пары; за границей окна 12 циклов предыдущая история не придумывается.

## Факты и ограничения сравнения

Сопоставляются точные ключи: цепь, слот A1/B1/B2, название упражнения и число снарядов. Представитель каждого варианта — последнее полное выполнение этого варианта в данном цикле, а не максимальный вес или более удобное старое наблюдение. В интерфейсе видны даты, все фактические подходы, кг одного снаряда, повторы и RPE упражнения.

Разницы кг и повторов на подход доступны только при полностью записанных одинаковых рабочих весах/повторах внутри каждого наблюдения, одинаковом подсчёте на сторону, силовом режиме, количестве подходов, причине дозы и целевом RPE. При разных вариантах, количестве снарядов или цепях строки показаны отдельно без переноса кг. Смешанные подходы, нехватка записей, симптомы, изменение дозы и неизвестные условия явно ограничивают сравнение. Для веса тела неизвестные кг не подменяются нулём.

Разницу RPE можно увидеть только при одинаковых кг, повторах и дозе двух наблюдений. RPE всего занятия не заменяет RPE упражнения. Фактическое изменение нагрузки не называется доказанным приростом силы; расчёт 1ПМ не добавляется. Плановые веса и повторы не подменяют отсутствующий факт.

## Решения тренера и ReadySix

На каждой фактически выполненной тренировке берётся snapshot `methodology.coachCycleDecision`, если он относится к предыдущему циклу и точной цепи/слоту. Показаны сохранение/смена варианта, удержание/обычная прогрессия, комментарий и отложенное применение по симптомам или доступности выбора. Если решения менялись внутри цикла, сохраняются наблюдения с датами и исходными ревизиями. Позднее редактирование решения через API не переписывает сравнение выполненных планов. Отсутствующий snapshot прямо обозначается, текущая версия решения вместо него не подставляется. Наблюдения не используются для автоматического утверждения, что решение вызвало результат или было нарушено игроком.

Сохранённый контекст ReadySix показан отдельно для полных выполнений каждого цикла: партии, нагрузка на площадке, поездки, причины ограничений и пропуски данных. Перекрывающиеся окна нагрузок не суммируются в выдуманный общий объём. Новая оценка готовности не создаётся.

## Реализация и проверка

Сервер строит `cycle.comparison` внутри существующего обзора; API сохраняет авторизацию, no-store и разделение по пространству/игроку. Сравнение только читает данные: сохранённые программы, результаты, решения и логика генерации не меняются.

739 тестов: 738 успешно, один пропущен. Production-сборка прошла. Проверены фактическое завершение/отмена, неизменность исторического решения, разные цепи/варианты/снаряды, RPE, повторы на сторону, неполные/смешанные записи, будущие даты, смена дозы, пересечение циклов и повреждённые метаданные решения. API проверен для обоих пространств с отказом без ключа и изоляцией данных. В локальном браузере проверены синтетические сравнительные карточки и раскрытие решений; реальные записи не изменены.

## Дальше

Проверить серверный кандидат и опубликовать ревизию. После двух завершённых циклов открыть обзор нового цикла, оценить фактические изменения и контекст, затем сохранить решения для следующего. Следующее расширение — управляемое тренером снижение объёма конкретных движений с причиной и последующей проверкой результата в сравнении циклов.
