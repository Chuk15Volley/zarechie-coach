# Фоновая командная очередь и публикация — 2026-10-12

Одинаковая реализация для zarechie и nkperf. ReadySix остаётся единственным источником состояния и ограничений. Силовая методика, циклы, запреты упражнений и полноценная разрешённая нагрузка здоровых областей сохранены.

## Выполнение

В существующем российском gym-контейнере supervisor запускает Next и отдельный worker. Остановка любого процесса завершает контейнер для существующей политики перезапуска. Секреты, сеть провайдера, Valkey и read-only корень сохранены. Worker работает через уже защищённые локальные API, с действующими лимитами и блокировками генерации. Дополнительных публичных служебных API нет.

Valkey хранит индекс активных очередей, неизменный запрос и идентификаторы заданий, управление running/paused/cancelled, отложенные повторы временных HTTP-ошибок. Общая 90-секундная lease ограничивает проходы worker; до трёх запросов за проход, HTTP timeout 65 секунд. После перезапуска используются прежние задания. Пауза прекращает следующие обращения; уже начатая работа может завершиться. Отмена окончательна для очереди, сохраняет готовые черновики и позволяет создать новую. Ни одно действие автоматически не публикует программу.

Браузер только показывает серверное состояние. Закрытие вкладки не останавливает генерацию. Видимый активный экран обновляется раз в 10 секунд, завершённый — раз в 30, скрытый — раз в 60. Для изолированной проверки кандидата worker отключается через GYM_TEAM_WORKER_ENABLED=0; production по умолчанию включает его.

## Групповая публикация

Кнопка публикует только отмеченные тренером готовые и ещё не сохранённые программы. Для каждой программы заново запрашивается ReadySix без кэша. Сравнивается SHA-256 отпечаток решения, симптомов/медицинской истории, календаря и площадочной нагрузки плюс запретов тренера, зафиксированный при генерации. Время формирования HTTP-ответа не влияет на отпечаток. Медицинские данные не копируются в мониторинг и не отправляются модели.

Изменение данных или старый черновик без отпечатка снимают отметку проверки; требуется обновить черновик. Медицинские паузы, блокирующее качество и необходимость медицинской проверки требуют индивидуального открытия и сохранения. Не пересчитывается новое состояние готовности и не ослабляются медицинские ограничения.

Используется общий путь индивидуального сохранения: история, циклы, запреты, нормализация упражнений, версии и индексы. Atomic Lua проверяет принадлежность проверенному batch, действующую блокировку публикации и отсутствие ранее сохранённой программы по основному и legacy ID перед всеми записями. Отдельно сохранённые программы не перезаписываются. Результат сообщается по каждому игроку; частичный успех не обозначается успехом всей команды. Повтор после потерянного ответа пропускает уже сохранённые программы.

## Мониторинг

События сохраняются как прежде. Технический сбой становится устранённым при готовности того же задания или успешного явного повтора по сохранённой цепочке идентификаторов. Активные и устранённые события показаны отдельно; health учитывает только активные. Отдельно виден свежий сигнал фонового worker. Исторические ошибки не удаляются.
